# Что происходит со свёрткой, когда аргументов нет?

Разберём утверждение: «Пустая унарная fold expression допустима только для `&&`, `||` и `,`. Результаты соответственно `true`, `false` и `void()`». Нам важно понять не только правило, но и то, зачем оно понадобилось.

## 1. Что такое пустой пакет?

```cpp
template<class... Args>
void f(Args... args) {
    std::cout << sizeof...(args) << '\n';
}
```

`class... Args` означает, что число типов может быть любым, включая ноль. `Args... args` создаёт соответствующий пакет параметров функции. `sizeof...(args)` считает элементы, а не байты.

```cpp
f(10, 20, 30); // 3
f(10);         // 1
f();           // 0
```

В последнем вызове компилятор выводит пустой пакет типов и создаёт функцию без аргументов. Пока никаких проблем нет.

## 2. Что сворачивать, если аргументов нет?

Попробуем сложить все числа:

```cpp
template<class... Args>
auto sum(Args... args) {
    return (args + ...);
}
```

`(args + ...)` — унарная правая свёртка. Унарная здесь означает, что имеется только выражение с пакетом, без отдельного начального операнда. Сам оператор `+` остаётся бинарным.

| Вызов | Раскрытие | Результат |
|---|---|---|
| `sum(1, 2, 3)` | `1 + (2 + 3)` | 6 |
| `sum(1, 2)` | `1 + 2` | 3 |
| `sum(1)` | `1` | 1 |
| `sum()` | Нет операндов | Ошибка |

Для одного аргумента оператор вообще не вызывается. Для нуля аргументов не осталось даже выражения, которое можно вернуть. Стандарт не задаёт результат пустой унарной свёртки по `+`.

Если каталог сборки ещё не настроен, выполните из корня проекта `cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug`. Запустите [`26_unary_sum.cpp`](examples/26_unary_sum.cpp): `cmake --build build --target run-theory-26_unary_sum`. Раскомментируйте `sum()` и пересоберите, чтобы увидеть ошибку. Верните комментарий для дальнейшей сборки.

## 3. Почему `&&` возвращает true?

Представьте проверку: все ли задания студента выполнены? Если хотя бы одно не выполнено, ответ «нет». Если заданий вообще нет, нет ни одного нарушения условия.

```cpp
template<class... Args>
bool all(Args... args) {
    return (args && ...);
}
```

`all(true, true, false)` раскрывается в `true && (true && false)` и возвращает `false`. `all()` возвращает `true`.

Почему это разумно? Для встроенного логического И `x && true` имеет то же логическое значение, что `x`. `true` — нейтральный элемент. Аналогичный алгоритм на обычном контейнере выглядит так:

```cpp
bool all(const std::vector<bool>& values) {
    bool result = true;
    for (bool value : values) {
        result = result && value;
    }
    return result;
}
```

Если контейнер пуст, цикл не выполнится. Начальное значение останется `true`. Это иллюстрация логического смысла, а не описание того, как компилятор реализует свёртку. В математической логике это называется вакуумной истинностью.

## 4. Почему `||` возвращает false?

Теперь вопрос иной: выполнил ли студент хотя бы одно задание? Если заданий нет, найти выполненное невозможно.

```cpp
template<class... Args>
bool any(Args... args) {
    return (args || ...);
}
```

`any(false, true)` даёт `true`, `any(false, false)` — `false`, `any()` — `false`.

Нейтральный элемент логического ИЛИ — `false`: `x || false` имеет то же логическое значение, что `x`. В цикле мы начинали бы с `bool result = false` и объединяли значения с помощью `||`. Для пустого контейнера вернули бы `false`.

Для встроенных `&&` и `||` сохраняется короткое замыкание; перегруженные операторы не обязаны обладать таким поведением. В наших примерах аргументы — bool.

## 5. Что значит void() для запятой?

Сначала обычный встроенный оператор запятая:

```cpp
int x = 0;
int result = (x = 10, x = 20, x + 5);
```

Сначала x становится 10, затем 20, затем вычисляется 25. Левый операнд вычисляется раньше правого, его результат отбрасывается; результатом всего выражения является результат правого операнда. Это не запятая между аргументами функции.

Теперь напечатаем все аргументы:

```cpp
template<class... Args>
void print_all(Args... args) {
    (static_cast<void>(std::cout << args << ' '), ...);
}
```

`static_cast<void>` означает: выполнить вывод, но отбросить значение выражения. Здесь это ещё и гарантирует использование встроенной запятой: её операнды имеют тип void.

Для `print_all(10, "Hello", 3.14)` получится последовательность трёх действий:

```cpp
(static_cast<void>(std::cout << 10 << ' '),
 (static_cast<void>(std::cout << "Hello" << ' '),
  static_cast<void>(std::cout << 3.14 << ' ')));
```

Слева направо выводятся `10 Hello 3.14 `. Если аргументов нет, никакого действия делать не нужно. Стандарт определяет выражение пустой свёртки как `void()`.

```cpp
int main() {
    void(); // корректное выражение без значения и побочных эффектов
}
```

Это не вызов функции с именем void. Это выражение типа void. Поэтому `print_all()` ничего не печатает. В проекте рейтинга `emit` уже возвращает void, поэтому отдельный cast не нужен; после свёртки остаётся `out << '\n'`, так что пустая строка отчёта печатает перевод строки.

## 6. Почему компилятор не подставит ноль для +?

Ноль — нейтральный элемент сложения чисел. Но `+` также объединяет строки, где нейтральный элемент — `std::string{}`. Пользовательский тип может определить совершенно другую семантику `+`. В пустом пакете даже нет типа первого аргумента, на который можно ориентироваться.

Это мотивация правила: стандарт не выбирает произвольный нейтральный элемент автоматически. Если он нужен, программист указывает его явно.

## 7. Как исправить sum: бинарная свёртка

```cpp
template<class... Args>
auto sum(Args... args) {
    return (0 + ... + args);
}
```

Теперь есть начальное значение `0`, поэтому это бинарная левая свёртка. Раскрытие:

| Вызов | Выражение | Результат |
|---|---|---|
| `sum(1, 2, 3)` | `((0 + 1) + 2) + 3` | 6 |
| `sum(1)` | `0 + 1` | 1 |
| `sum()` | `0` | 0 |

Для произведения вместо нуля используем единицу: `(1 * ... * args)`. Начальное значение должно иметь подходящий тип и семантику: для строк, например, `(std::string{} + ... + args)`. Это не универсальная функция для любого типа с `operator+`.

## 8. Проверяем всё вместе

Полная программа: [`25_empty_folds.cpp`](examples/25_empty_folds.cpp).

```bash
cmake --build build --target run-theory-25_empty_folds
```

Ожидаемый вывод:

```text
false
true
true
false
[10 Hello 3.14 ]
[]
6
0
24
1
```

| Оператор | Унарная свёртка без аргументов | Бинарная с начальным выражением |
|---|---|---|
| `&&` | `true` | `(true && ... && args)` |
| `\|\|` | `false` | `(false \|\| ... \|\| args)` |
| `,` | `void()` | `(void(), ... , args)` |
| `+` | Ошибка | `(0 + ... + args)` |
| `*` | Ошибка | `(1 * ... * args)` |

**Итог:** пустая унарная свёртка имеет значение только для трёх указанных операторов. Бинарная свёртка при пустом пакете раскрывается в начальное выражение, даже если оно не является математически нейтральным элементом.
